# ANCA service texts as answer key: access and format

Issue: cmbryan/yocal#9 (map #5). Researched 2026-10-29. Sources: antiochian.org pages viewed in a browser, anonymous HTTP HEAD/GET of the public PDF/RTF files, text extraction (`pdftotext -layout`) of 2026 files. PDFs downloaded to scratch only, none committed. Short paraphrase only (HTM copyright, see Terms).

## TL;DR

- **Usable as answer key.** Public static files, no auth, curl works. Nearly every Sunday has Great Vespers (Sat eve), Orthros, Liturgy Variables, and an "Abbreviated Rubrics" summary with HTM book page cites.
- **Coverage:** Sat/Sun pairs 2018-02-17 .. 2026-11-22 (rolling ~4-5 wk ahead; Nov 29 only Bilingual so far). ~85-90% of weekends by date-pattern URL; the rest (Pascha cycle, Pentecost, feast-coincident Sundays) use non-date filenames, reachable only via the `liturgicday` page link list.
- **Parseability:** medium. Text-based Word-exported PDFs, consistent ALL-CAPS slot headings with tone and melody tags. RTF also published. No JSON/structured feed publicly; the site's JSON API is behind a bearer token (not used, see Access problems).
- **Biggest catch for the map:** feast and Paschal-cycle files are not date-keyed; id-to-date mapping is linear only for recent ids.

## 1. liturgicday id -> date

- `https://www.antiochian.org/liturgicday/<id>` is an Angular SPA; `curl` returns only an empty shell (`<app-root>`). Needs a browser to render.
- **Linear for recent ids:** `id = 4724 + (date - 2026-11-01)` in days. Verified: 4724=2026-11-01, 4723=2026-10-31, 4670=2026-09-08, 4521=2026-04-12, 4513=2026-04-04, 4413=2025-12-25, 4360=2025-11-02, 4000=2024-11-07, 3800=2024-04-21, 4752=2026-11-29, 4778=2026-12-25.
- **Not linear earlier:** id 1500 = 2018-02-03 (linear formula predicts 31 days later); ids 724, 3000, 3500 render an empty page (no date). So early ids are sparse/gapped; linear holds at least 2024-04-21 -> 2026-12-25.
- **Forward end:** id 4778 (2026-12-25) renders the date and readings but no service-text links; 4785 and 4800 empty. Calendar apparently ends ~2026-12-31 (id 4784, unverified).
- Page content per day: header date, feast/saint title, Epistle and Gospel (with refs), fast info, "Daily Liturgical Text" link list, permanent resources (Great Intercession, Paraklesis, reader instructions) and seasonal calendars (2026 Sunday readings chart, 2026 fasting calendar PDFs). Page footer states the saints/readings listing is generated by the GOA Online Chapel and used with permission.
- Day data comes from `GET /api/antiochian/LiturgicalDay/<id>`, `/LiturgicalTexts/<YYYY-MM-DD>`, `/LiturgicalTexts/CalendarDates` etc. (seen in browser network log). All return 401 without a bearer token.

## 2. File URL patterns

Base: `https://www.antiochian.org/servicetexts/<name>`; 301-redirects to `https://antiochianprodsa.blob.core.windows.net/servicetexts/<name>` (Azure blob, anonymous GET/HEAD OK, 200 or 404 per file, no listing: container list returns 405).

Regular (date-keyed) pattern: `<Mon> <DD> <YYYY> <SUFFIX>.<pdf|rtf>`, URL-encoded spaces.

| Suffix | Content | Keyed by |
|---|---|---|
| `VESP` | Great Vespers (Saturday) or Daily Vespers (weekday, seen Wed) | date the service is served; title says the next day's date ("served on the evening prior") |
| `ORTHROS` | Sunday Orthros (full text incl. fixed parts, 16 pp) | Sunday |
| `READ` | Divine Liturgy Variables (2-3 pp) | Sunday |
| `Abbr` | Abbreviated Rubrics: whole weekend (Sat Vespers, Orthros) as numbered steps with HTM page cites, ends "Liturgy: see Variables" | Sunday |
| `Bilingual VESP/ORTHROS/READ` | English + Arabic two-column (verified on READ) | same |

Notes:
- **Month spelling varies:** `Sep` mostly but `Sept` on some feast files; `June`, `July`, `March`, `April` spelled in full on some (e.g. `June 07 2026 READ.pdf`, `July 05 2026 READ.pdf`); `Jan Feb Aug Oct Nov Dec` abbreviated. A scraper must try both spellings. Naive `%b` probing falsely shows Jun/Jul "gaps".
- **Feast/Paschal files have no year and often no date:** Nativity `3 Nativity ORTHROS.pdf`, `4 Nativity Read JOHN.pdf` (2025-12-25, plus date-keyed Bilingual); Pascha 2026 `9-Paschal-READ.pdf`, `11B-Agape-VESP.pdf`, `16 Pascha Read Bilingual.pdf`; Lazarus Saturday/Palm Sunday `2-Laz-Sat-ORTHROS.pdf`, `3-Laz-Sat-READ.pdf`, `4-Palm-Sunday-VESP.pdf`, `5-Palm-Sunday-LITART.pdf` (LITART = liturgy variables? meaning unverified), Nativity of Theotokos 2026 `Sep 08 VESP.pdf` / `Sept 08 READ.pdf` (no year). Filenames embed a service-sequence number; likely reused across years (not verified). These links appear only on the `liturgicday` page, so need the rendered page (or the token-gated API).
- RTF mirror exists for every PDF (`.rtf`; Word-generated, checked Nov 1 2026 READ.rtf, ~120 KB).
- Suffixes that do not exist (404): `MATINS`, `Vesp`, `Bilingual Abbr`. No Sunday-evening Vespers file (Sunday Vespers not published as date-keyed `VESP`).

## 3. Coverage (HEAD probes, weekly Sundays/Saturdays, 2018-01 .. 2026-11, month-spelling variants tried)

- Earliest: Sun 2018-02-18 (READ, ORTHROS, Abbr) and Sat 2018-02-17 (VESP). Nothing earlier at date-keyed names (probed Sundays 2013-12 .. 2018-02, all 404, but only with abbreviated-month spelling, so Mar/Apr/Jun/Jul/Sep 2014-2017 not fully ruled out; liturgicday id 1500 for 2018-02-03 exists but has no texts).
- Latest: Sun 2026-11-22 (all four); Sat 2026-11-21 VESP. Sun 2026-11-29: only Bilingual ORTHROS + Bilingual READ exist so far (English and Abbr not yet). Nothing for Dec 2026 or later (Dec 25 2026 page has no links).
- Lead time: Last-Modified on files: Nov 1 READ = Oct 26 (6 d before); Nov 22 READ = Oct 27 (26 d); Nov 29 Bilingual = Oct 27 (33 d); Sep 6 READ = Aug 23. So ~1 month ahead, files get (re)uploaded; may be revised.
- Per year, Sundays with a date-keyed `READ.pdf` (same counts for ORTHROS, Abbr; VESP matches Saturdays): 2018 43/52 (from Feb), 2019 48/52, 2020 49/52, 2021 49/52, 2022 48/52, 2023 49/53, 2024 49/52, 2025 48/52, 2026 44/48 (to Nov 22).
- **Missing date-keyed Sundays** are Paschal cycle / feast-coincident / non-standard names, e.g. Pascha and Palm Sunday or Pascha+1 (2018-04-01/08, 2019-04-21/28, 2020-04-12/19, 2021-04-25/05-02, 2022-04-17/24, 2023-04-09/16, 2024-04-28/05-05, 2025-04-13/20, 2026-04-05/12), Pentecost (2026-05-31, 2018-05-27, 2020-06-07, 2021-06-20, 2022-06-12, 2023-06-04, 2024-06-23, 2025-06-08, 2019-06-16), Sundays on Nativity/Theophany/other Great Feasts (2022-12-25, 2019-01-06, 2023-08-06 Transfiguration, 2025-09-14 Elevation). Not investigated whether the same Sundays carry feast-named files on the page. All of these are in scope (Major feasts) so need page-driven link discovery.
- Weekday Vespers: Wednesday `VESP` observed Sep-Nov 2026 ("Daily Vespers of Thursday ..."); other weekdays not probed (out of map scope).

## 4. PDF structure (2026 files; older ones differ slightly)

Producer: Microsoft Word, tagged PDF, embedded fonts; `pdftotext -layout` gives clean text. Page footer on each page: date, doc kind + page no., short day title. Core titles in PDF info: "Divine Liturgy Variables", "Great Vespers", "Daily Vespers", "Sunday Orthros", "Abbreviated Rubrics".

Header block (all docs): kind + date ("Divine Liturgy Variables on Sunday, November 01, 2026" / "Great Vespers of Sunday, November 01, 2026; Tone 5" / "Orthros on Sunday ...; Tone 5 / Eothinon 11"), then feast/saint commemoration lines (combined into one name list), Vespers adds "(served on the evening prior)". Header format drifts by year (2018: "Great Vespers on Saturday, February 24, 2018; Tone 5", "Tone 5 / Eothinon 5").

Slot labels (ALL-CAPS headings, mixed words, tags in parens):
- Form: `<SLOT> [FOR <saint/feast>] IN TONE <N> (<melody tags>)`. Examples: `RESURRECTIONAL APOLYTIKION IN TONE FIVE (KAZAN) (CROW-MP3)`, `APOLYTIKION OF SS. COSMAS AND DAMIAN OF ASIA IN TONE EIGHT`, `ORDINARY KONTAKION IN TONE TWO (CHANT) (CHORAL)`, `DOXASTICON FOR SS. COSMAS AND DAMIAN IN TONE SIX`, `THEOTOKION FROM THE OCTOECHOS IN TONE FIVE (KAZAN) (STAM)`, `SATURDAY PROKEIMENON IN TONE SIX`, `THE ELEVENTH EOTHINON GOSPEL`, `AINOI (PRAISES) IN TONE FIVE`, `THE KATAVASIAE OF THE THEOTOKOS CANON IN TONE FOUR`. Tone written as a word in headings; digits in header.
- Tags in parens = melody/arrangement sets (Kazan, Karam, Stam, Crow, El Massih, Choral, Chant) or "(**The original melody**)". Useful as provenance for the music side, not for text selection.
- Vespers stichera (Lord I Have Cried): sub-headings per source, e.g. "For the Resurrection from the Octoechos in Tone Five (STAM)" then numbered "Verse 10 ... Verse 4" with a psalm verse then the hymn; so the **count and split** (here 6 resurrectional + 4 saint = 10) is encoded by the verse numbers. Octoechos/Menaion source tags appear only in the Abbr file.
- Sat Vespers slots seen (Nov 1 2026): Great Litany, Lord I Have Cried (10 stichera), Doxasticon, Theotokion (Octoechos tone of the week), Gladsome Light, Saturday Prokeimenon (tone 6), Litany of Fervent Supplication, Evening Prayer, Litany of Supplication, Peace, Aposticha (resurrectional + saint stichera + Doxasticon + Theotokion), Hymn of Simeon, Trisagion, Resurrectional Apolytikion + saint apolytikion + Theotokion (Tone 8 here), Dismissal.
- Orthros slots seen: Psalms 3/37/62/87/102/142 (full text), Great Litany, Resurrectional + saint apolytikion + Theotokion, Kathismata hymns (tone), Evlogetaria, Anabathmoi, Prokeimenon, Eothinon Gospel (number + text), Psalm 50 + troparia, Intercession, Kontakion/Oikos/Synaxarion, Katavasiae (canon tone), Magnifications, Exaposteilaria (eothinon + saint), Ainoi (Praises, 8 stichera), Doxastikon, Great Doxology, Dismissal troparion.
- Liturgy Variables (full list, Nov 1 2026): little-entrance instruction + eisodikon, resurrectional apolytikion, saint apolytikion, patron-saint placeholder (rubric), ordinary/alt kontakion (Theotokion Tone 2), Epistle (prokeimenon + verse, saint "for Ss. X" subtitle + Pauline ref + text), Gospel (Fifth Sunday of Luke + ref + text), dismissal with the day's saints inserted. Includes concrete refs: "(12:27-13:8)" and "(16:19-31)". Fixed Liturgy text ("continues as usual") omitted. Compact, ideal answer key.
- Abbr file: per service a numbered rubric list ("We chant ... in Tone 5 with ten stichera", "kathismata hymns from the Octoechos for Tone 5 (HTM Octoechos 237-238)", "The eleventh Eothinon Gospel (John 21:14-25)") with **HTM book + page citations** ("HTM Octoechos 234", "HTM Nov. Menaion 5", "HTM Horologion Vol. 1, 90") before each hymn block. Highly valuable: gives the Octoechos/Menaion page per slot, beyond the text.
- Readings: Epistle/Gospel with chapter:verse and fragments (e.g. 12:27-13:8 vs 12:27-31;13:1-8 as shown on the web page; PDF text uses the saint's Epistle, so Epistle in the PDF may differ from the day's page listing: Nov 1 PDF "(For Ss. Cosmas and Damian of Asia)" while page shows 1 Cor 12:27-31;13:1-8; same pericope, different notation).

## 5. Machine-parseability

- Text extraction works (`pdftotext -layout`). Headings are uppercase lines with centered layout; hymn bodies are plain paragraphs; verses numbered. Regex-able: header `^\s*(Great Vespers|Orthros|Divine Liturgy Variables)...`, slots `^[A-Z0-9 ,.&()/*:'’-]{12,}$`, tone `IN TONE (ONE|TWO|...|EIGHT)`, `(HTM <book> <page>)` in Abbr, scripture refs `\((\d+:\d+[-–,;\d: ]*)\)`.
- Gotchas: wrapped headings (two-line titles), ordinal/tone words not digits in slot titles, stray footnote digits in headings ("THE INTERCESSION1"), centered layout loses column order in Bilingual (two columns, Arabic RTL), date/title header changes by year, "(**The original melody**)" markers.
- Compare strategy: slot headings are stable enough to parse into a list of (slot type, tone, saint-attribution, source) and to compare with the rule engine output; hymn text itself should not be compared (HTM copyright, and unnecessary).
- Answer-key limits: the key records *what was chosen*, not *why* (no rule explanation); Abbr rubrics occasionally say "as usual". Uses Antiochian (North American) calendar: includes North American saints in places and can diverge from UK calendar data (UK divergence log).

Consequence for this repo: keep PDFs/RTFs out, no long verbatim excerpts (as map notes); derived slot tables (slot type/tone/source cites/ref numbers) are factual and fine.

- Contact for the guide: Fr Peter Samore, OLG@antiochian.org (Online Liturgical Guide). Author metadata in 2026 PDFs: Peter Samore.

## 7. Access problems / not done

- liturgicday pages need JS; plain curl/WebFetch gets an empty shell. Playwright works.
- `/api/antiochian/*` returns 401 (`WWW-Authenticate: Bearer`); the SPA obtains an anonymous token via POST `/connect/token` and stores it in localStorage. I tried to fetch the API from the page context using that token; the harness blocked it (website access circumvention), and I did not work around it. So id->date for early ids, and complete per-day file lists (incl. feast filenames), were taken only from rendered pages I loaded manually (about 15 ids).
- Hence open: (a) full list of feast/Paschal filenames for all in-scope Major feasts and years; (b) where the id mapping breaks between 2018 and 2024-04; (c) whether feast files reused across years; (d) whether past-year files get revised. Next step if wanted: ask OLG@antiochian.org for a file index or permission to use the API, or script a headless browser to read each in-scope date's page (id formula above works for 2024-04 on).
- Scan method: anonymous HEAD requests to the static blob host, ~2,000 total, sequential; low volume.

## 8. Recommendation for the answer-key design

- Use date-keyed `Abbr.pdf` (rubrics + HTM cites + all texts for Sat Vespers/Orthros) and `READ.pdf` as primary key per Sunday; `VESP.pdf` for Sat Great Vespers detail. Weekends 2018-02 .. 2026-11 give ~430 Sat/Sun pairs of regular days, covering all tones/Octoechos cycle and Triodion/Pentecostarion Sundays.
- Major feasts and the Paschal cycle: need page-driven discovery of filenames; scope as separate harness input list.
- Parsing target: slot headings + tone + attribution (+ HTM page cites from Abbr), not hymn text.
